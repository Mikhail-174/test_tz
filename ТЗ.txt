Тестовое задание: Система учёта работников компании
Легенда
Вам нужно разработать внутреннюю систему для HR-отдела компании, которая позволит вести учёт работников: добавлять новых сотрудников, просматривать список, обновлять данные и управлять статусами. Система должна иметь REST API и админ-панель.

Технический стек
Python 3.10+
Django 4.2+ (LTS) + Django REST Framework
Poetry для управления зависимостями
БД на выбор (SQLite/PostgreSQL)
Функциональные требования
1. Модель данных Worker
Обязательные поля:

first_name — имя
middle_name — отчество (необязательное)
last_name — фамилия
email — email (уникальный)
position — должность
is_active — активен ли работник (по умолчанию True)
hired_date — дата приёма на работу (автоматически при создании)
created_by — пользователь, создавший запись (ForeignKey)
Подумайте:

Какие поля должны быть обязательными, а какие нет?
Нужны ли индексы на каких-то полях?
Есть ли другие технические поля, которые полезно добавить? (например, для аудита, мягкого удаления и т.д.)
2. REST API
Endpoints:

GET /api/workers/ — список работников
POST /api/workers/ — создание работника
GET /api/workers/{id}/ — детальная информация
PATCH /api/workers/{id}/ — обновление
DELETE /api/workers/{id}/ — удаление
POST /api/workers/import/ — импорт работников из Excel
Требования к API:

Пагинация списка (размер страницы на ваше усмотрение)
Список работников: отображать только базовые поля (id, first_name, middle_name, last_name, position, is_active)
Детальный просмотр: все поля включая email, hired_date, created_by
Фильтрация по is_active и position (обязательно)
Ролевая модель доступа:
User — только чтение (GET)
Admin — полный доступ (CRUD)
Автоматическое заполнение created_by при создании
Логирование/уведомление при создании работника (и через API и через админку) (достаточно вывода в консоль)
Импорт из Excel:

Endpoint принимает Excel файл
Валидация данных:
Проверка обязательных полей
Валидация email, проверка дубликатов
Возвращает отчёт: сколько записей добавлено, сколько ошибок с описанием
3. Django Admin
Фильтры по ключевым полям
Поиск
Возможность редактировать некоторые поля прямо из списка (например, is_active)
4. Тесты
Напишите тесты для проверки ключевой функциональности. Что именно тестировать и насколько глубоко — на ваше усмотрение.

Что оценивается

✅ Реализация бизнес-логики согласно требованиям
✅ Работоспособность API и админки
✅ Качество кода и соблюдение best practices
✅ Наличие тестов

Применяйте лучшие практики разработки на Django/DRF, которые вы знаете. Если считаете нужным добавить что-то сверх требований (логирование, docker, swagger, pre-commit hooks и т.д.) — будет плюсом.
